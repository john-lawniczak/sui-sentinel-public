First-pass commit: `f1acd55`. This is a code-quality and correctness review of the
Rust collector/report, not a smart-contract audit or verification of Suilend's
current deployed liquidation rules.

## Findings addressed

1. **Completion markers could be visible during serialization.** Write a sibling
   `.json.partial`, flush and sync it, then atomically hard-link the completed
   file into place without replacing existing output. Failure tests confirm a
   failed serializer publishes no marker and existing reports are preserved.
2. **Body disconnects/timeouts bypassed HTTP retries.** Retry the complete read
   operation, including response-body transport/decoding errors. Malformed JSON,
   GraphQL errors and permanent HTTP failures still fail closed. A local server
   deliberately disconnects mid-body to exercise the regression. Honor numeric
   Retry-After up to ten seconds; bound attempts to four.
3. **HTTP response buffering was unbounded.** Cap decompressed responses at 64 MiB.
   Retain request deadlines, shared concurrency limits, disabled redirects, and
   URL-stripped transport errors. A regression verifies query-string credentials
   do not appear in transport error output.
4. **Offline replay trusted derived metadata too much.** Reconstruct market table,
   type and count from raw contents; validate object IDs, provenance, owner
   addresses, reserve membership, duplicate records and manifest consistency.
   Corrupted input tests verify failure before a completed report is published.
5. **Repeated JSON clones amplified allocation costs.** Move response subtrees
   through parsing with `Value::take`; retain raw data once per record. Group
   collection context in a small struct instead of an eight-argument function.
6. **Diagnostic and ownership coverage needed clearer boundaries.** Parse all
   asset diagnostics before mutating aggregates, mark unsupported positions
   unavailable, and classify missing address-owner data as unresolved. Add direct
   wallet debt aggregation alongside position concentration. Zero cached weighted
   debt with borrow evidence is unknown, never asserted debt-free.

7. **Full-census testing disproved one-cap-per-position ownership.** The main
   market contains ten obligations with multiple owner caps (eleven extra caps).
   The public source includes `new_obligation_owner_cap` for admin recovery.
   Preserve every capability, mark these positions ambiguous, and exclude them
   from single-wallet debt attribution. Do not fail the census or double-count
   exposure. A dedicated regression tests the join.

## Remaining boundaries

Reports depend on the queried provider and retained files; object digests are
preserved but are not cryptographically recomputed from BCS. A capture is a census
of obligations and visible owner caps, not all deposit holders. Wrapped caps may
not be discoverable through the type index. `--all-markets` includes unendorsed
market instances and keeps them separate. A failed crawl requires a fresh run;
there is no resume support. Filesystems must support hard links for completion
publication. Price/interest refresh, stress losses, executable liquidation
liquidity and overall grades remain unavailable until the research gate is resolved.

## Economic stress and presentation review

First-pass commit: `9f6314c`. Reviewed per-position repricing, score normalization,
coverage/valuation gates, report compatibility, exporter validation, and the
provisioned presentation. This is an arithmetic and software review, not
validation of deployed liquidation execution or economic scenario calibration.

Changes from the quality pass:

- Reuse a small pending-results buffer instead of allocating a vector and cloning
  scenario names for each position. Commit totals only after every scenario for
  that position succeeds. A later-scenario overflow regression proves no partial
  mutation survives and the accumulator remains usable.
- Move exact decimal serialization into a shared module, removing the stress
  policy's dependency on report types.
- Reconcile stress exclusions with unsupported diagnostics and unknown cached
  debt; reject inconsistent shortfall counts and attempts to publish any economic
  score from a cached report.
- Preserve null/unknown color mappings when adding panel-specific mappings.
  Share readable status labels across coverage and score-availability tables.
- Resolve four generic `COIN` labels using recorded public metadata. Full coin
  type identity is retained; display aliases do not affect stress factors.
- Remove the obsolete negative test for abandoned `run`/`verify` placeholders and
  stale command references. Keep operational scripts and current regression tests.

Validation: formatting, Clippy with warnings denied, all 37 Rust tests, generated
dashboard consistency, line limits, and Prometheus metric lint pass. The running
Grafana check compares provisioned styles/layout and executes 25 queries for all
markets and one market; asset and scenario totals reconcile with the saved report.
Browser initialization still fails with the previously recorded runtime error;
visual rendering and interactive selection remain unverified.

The full stress replay evaluates 159,688 positions and excludes 29 with unknown
cached debt. All 26 market economic scores remain null. Audited output is
byte-identical to the first-pass stress report for both JSON and NDJSON. One local
release replay took 2.020 seconds and 179.4 MiB peak RSS on macOS; this is a single
measurement, not a throughput guarantee. The active artifact is
`snapshots/mainnet-2026-10-19/analysis-stress-v1/report.json`; original captures and
prior reviewed artifacts remain retained for provenance. Temporary audit replays
and helper files are removed after validation.
